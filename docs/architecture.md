# Архитектура бэкенда

*Обзорная глава: структура серверной части, назначение компонентов и план улучшений перед фронтендом и развёртыванием.*

## Общая архитектура

Серверная часть построена на **FastAPI** по слоистой архитектуре:

- **API-слой** (`app/routers/`) — принимает HTTP-запросы, проверяет входные данные (Pydantic-схемы), вызывает сервисы;
- **Сервисы** (`app/services/`) — бизнес-логика: семантический матчинг, GPT-анализ, чат, импорт вакансий;
- **Данные** (`app/models.py`, `app/database.py`, `alembic/`) — ORM-модели, подключение к PostgreSQL, миграции;
- **Ядро** (`app/core/`) — конфигурация и обработка ошибок;
- **Безопасность** (`app/auth.py`) — аутентификация по JWT, роли.

## Структура файлов

```
app/
├── main.py              — точка входа: FastAPI, lifespan (планировщик), роутеры, обработчики ошибок
├── auth.py              — JWT, get_current_user, require_admin
├── database.py          — engine, SessionLocal, Base, get_db
├── models.py            — ORM-модели: User, Vacancy, ChatMessage
├── schemas.py           — Pydantic-схемы (валидация запросов/ответов)
├── logging_config.py    — логирование (app.log + консоль)
├── core/
│   ├── config.py        — Settings (pydantic-settings, .env)
│   └── errors.py        — единый формат ошибок
├── routers/
│   ├── users.py         — /register, /login, /me, /me/skills, /me/resume, /me/matches, /me/analysis, /me/chat
│   └── vacancies.py     — CRUD вакансий, поиск и фильтры
└── services/
    ├── matching.py      — семантический матчинг (sentence-transformers + кэш эмбеддингов)
    ├── gpt_analysis.py  — GPT-анализ навыков (пробелы + план)
    ├── chat.py          — чат-консультант с памятью
    └── vacancies_import.py — парсер hh.kz + планировщик

alembic/     — миграции БД (6 миграций + env.py)
tests/       — тесты (test_main.py — API, test_matching.py — ИИ-ядро)
docs/        — документация (gpt_plan.md, production_notes.md, architecture.md)
experiment/  — эксперименты (keyword vs семантика, бенчмарк)
```

## Компоненты

**API-эндпоинты:**
- Аутентификация: `POST /register`, `POST /login`
- Профиль: `GET /me`, `PUT /me/skills`, `POST /me/resume`
- Вакансии: CRUD `/vacancies` + поиск/фильтры
- ИИ: `GET /me/matches` (подбор), `GET /me/analysis` (анализ навыков), `POST /me/chat` (чат с памятью)

**Ключевые сервисы:**
- `matching.py` — семантический подбор, кэш эмбеддингов (~175× ускорение);
- `gpt_analysis.py` — GPT-анализ навыков (пробелы + план обучения);
- `chat.py` — чат с историей диалога в БД;
- `vacancies_import.py` — парсер hh.kz, планировщик обновления.

**Данные:** модели User, Vacancy, ChatMessage; 6 миграций Alembic; контроль соответствия через `alembic check`.

**Инфраструктура:** конфигурация pydantic-settings, единый формат ошибок, логирование, 11 тестов.

## Что улучшить перед фронтендом

- **CORS** — разрешить домен фронтенда (иначе браузер заблокирует запросы);
- **GET-эндпоинт истории чата** — чтобы интерфейс показывал прошлые сообщения;
- *(опционально)* стриминг ответов чата — эффект «печатающегося» текста.

## Что улучшить перед развёртыванием

- **HTTPS/TLS** — обеспечивается платформой развёртывания;
- **Dockerfile** — контейнеризация;
- **rate limiting** — защита логина и платных вызовов LLM;
- ограничение размера загружаемого резюме;
- запуск миграций при деплое, отдельная production-БД;
- очистка репозитория: `app.log` и `test.db` в `.gitignore` (логи и тестовая БД в git не нужны).

## Качество (по желанию)

- тесты на `/me/analysis` и `/me/chat` (с заглушкой вызова OpenAI);
- общий клиент OpenAI вместо создания на каждый запрос.

## Итог

Серверная часть функционально завершена: аутентификация, подбор вакансий, анализ навыков и диалоговый консультант работают и покрыты тестами. Дальнейшие шаги — фронтенд (визуальный слой) и развёртывание с учётом перечисленных улучшений.
